# PLAN

Design lives in the wiki (stateless-agent-architecture.md); this file only sequences phases.

## Milestone A — Runtime

- [x] Phase 0 — Workspace skeleton: `crates/{runtime,protocol,config}`; task contract (tool_call in → tool_result out); capability surface definition (fs scope, command exec, network — what a skill may touch; no credentials). Isolation model: **the Probe itself runs as a container** (base image + on-demand dependency install, e.g. Python + libs) — isolation is per-node, not per-skill. Consequence stated openly: skills inside one container share its filesystem; the "restricted world" is enforced by the capability surface (app-layer checks), not by container boundaries. Acceptable under user-namespace isolation (isolation cuts by user, not by skill); revisit per-skill isolation only if multi-tenant shared nodes become real.
- [x] Phase 1 — Runtime carriers: steel / python (PyO3) / wasmtime (the Wasm engine; wasmer/wasmi were engine candidates, not languages; koto/rune predate the three-language ruling and are dropped) + nushell (subprocess, CGI-shaped: JSON via stdin, structured result via stdout — completes the language-selection quadrant grid), feature-gated; per-operation language declaration; script-only operations end-to-end.

## Milestone B — Actuator

- [ ] Phase 3 — Outbound registration: deploy on any machine and it operates that machine. Connection-direction/data-direction decoupling: on startup the probe actively connects to the control plane and registers (presence + capability list), keeps the connection open, tasks are pushed down the connection (WS frames) — no inbound ports, network ingress topology irrelevant; long-polling is the degraded implementation. Probe is an Aura Actor type (actor_type = Probe, partition_key = node_id): the control plane's calls are standard `ctx.invoke()` routing — registration credential = user credential, capability list (the carried languages) written into the user's namespace registry; target resolution = user namespace + node alias + operation (`probe:home-pc:read_file`), where the operation is a registered actor/script — the Probe ships no built-in operations, every operation is user-written or AI-generated code delivered through a carrier (nushell/python/steel/wasmtime). Same-node seriality free via Actor mailbox semantics; timeout/error reuse `pending_calls` deadline scan.
- [ ] Phase 4 — Operation dispatch: the Probe never sees a skill. A skill is emergent in the Krystallizer graph; Gravity drives the LLM — the LLM selects the operation and generates its arguments, and that selection is the skill's execution. What the Probe receives is an operation, its declared language, its code, and its arguments. Two payload forms declared in the task context: `inline` (bytes in the frame — py/steel, KB-scale) and `link` (URL + content-hash version + expected hash — Wasm, MB-scale; optional control-plane HTTP port, CDN-cacheable by version, hash verifies bytes). Restricted networks (WS-only egress): `link` degrades to chunked delivery over the same WS channel — the control plane decides at frame assembly; the Probe consumes whichever form is declared. Zero cache: Gravity resolves against Krystallizer live on every tool call; the Probe holds nothing between calls and initiates no fetch of its own.
- [ ] Phase 4.5 — Host-side storage service (ADR-0010): a `#[kv_storage]` executor instance deployed alongside the actuator — remote VirtualStorage backends (e.g. a Krystallizer hosted on this machine) send op frames over the existing outbound WS connection; the executor prepends its declared prefix and executes against the local engine. No dedicated listener, no second protocol: KV rides the same connection as tool calls.
- [ ] Phase 5 — Scope constraints: fs scope, command exec, network declared per-probe registration and enforced on delivered scripts at execution. Whether an operation is AI-generated-live or pre-audited is control-plane policy (Gravity/Krystallizer), not a Probe concern. This is the ONLY containment layer (no per-operation container boundary beneath it) — the check must be enforced at execution, not just at dispatch-declaration.
- [ ] Phase 6 — Data-path discipline: control plane carries instructions and result summaries only — Result stays message-sized; large artifacts (files, binaries) are handled by the operation on the Probe side (local fs, user-configured transfer tooling, transport operations). Transport-reachability requirements (direct connection / same VPN) ride skill metadata on the Gravity side — the control plane neither knows nor governs the data path. AI-generated invoke arguments are instruction semantics (paths, options, fragments) and naturally bounded; a loose inbound message cap on the control plane guards anomalies only, it is not a data-plane design.

Deferred gates:

- Aura-embedded form (Wasmtime-heavy-isolation sibling): deferred until the remote actuator is stable; embedding changes nothing in the task contract.
- Skill packaging/install lifecycle: skills are emergent (Krystallizer graph), not installed artifacts — revisit only if cold-start cost of spec fetch becomes measurable.
